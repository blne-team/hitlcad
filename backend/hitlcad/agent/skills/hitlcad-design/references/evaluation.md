# Reviewing designs and evaluating skills

Use for an explicit critique or a deliberate skill evaluation. Ordinary design work needs only the
relevant observations, not a full benchmark ceremony.

## Review a design

Compare it against the brief, then inspect its functional layout, visual hierarchy, assembly and
manufacturing choices. Use the existing isometric/front/right/top previews consistently. Section
views help distinguish an attractive envelope from a workable internal arrangement.

Write critiques as observation → consequence → proposed change. For example: “The grip and nozzle
have similar visual weight, so the working direction is weak; reduce the secondary grip flare while
keeping its required contact envelope.” Tie comments to a view, part or feature so they can be acted
on. Do not replace the human's requested expressive style with a personal preference for restraint.

Keep three kinds of evidence distinct:

- Reported results: dimensions, fits, walls, interference and supported motion checks.
- Qualitative judgments: coherence, recognition, discoverability and user preference.
- Unresolved physical claims: comfort, loads, fatigue, airflow, vibration or thermal performance
  without the appropriate analysis or experiment.

## Evaluate a skill change

Prepare a fixed set of general CAD briefs before comparing conditions. Include parts, assemblies,
expressive objects, unfamiliar constructions and later edit requests. Use conditions such as operating skills alone, plus design skills,
and plus the selected style reference. Keep agent/model version, tool access, input brief and resource
budgets comparable; repeat runs when practical to expose model variability.

Measure requirement completion and unsupported claims, repair builds, tokens, and whether a later
edit preserves design intent. Count exploratory builds separately: useful concept comparison can
consume builds without being an error. Do not weaken the brief to improve first-build statistics.

For visual quality, compare equivalent views with similar framing and presentation, and conceal the
condition labels from human reviewers when practical. Ask about coherence, usefulness, adherence to
the requested direction and preference. Record disagreement rather than inventing an objective beauty
score. More detailed geometry or brighter rendering is not evidence of a better design.

For diversity, describe which arrangements, silhouettes or construction strategies differ. Different
names and colours alone do not demonstrate a broader solution space. Include a task where restraint
is appropriate and one where expressive variety is requested.

Retain a change when its intended benefit is supported without unacceptable regressions elsewhere.
Record tradeoffs when a style or exploration skill improves user preference at a resource cost.
Packaging and link checks validate distribution; only behavioral evaluation supports claims that
the skills improve design. No benchmark improvement is implied by this library's presence.
